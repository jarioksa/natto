tinyrox problems

Currently tinyrox is unusable and fails to build correct NAMESPACE and
Rd files. This is not only aesthetic issue of style, but natto fails
R CMD check with tinyrox. Unfortunately I still need to use roxygen2
which mangles DESCRIPTION and uses ugly air-formatting in Rd files.

Checked with tinyrox 0.3.3 on June 9, 2026

- Recognizes only S3 methods from a fixed list
  tinyrox:::KNOWN_S3_GENERICS plus generics defined within the
  package. KNOWN_S3_GENERICS is manually maintained in file
  namespace.R and it lacks as.dist and profile of stats. The design
  files to recognize generics imported from other packages and does
  not know eigenvals, scores and sppscores<- of vegan.  NAMESPACE
  exports these as export(as.dist.deldir) etc.  Should be
  S3method(as.dist,deldir) etc. In Rd files these are given as dotted
  names (as.dist.deldir instead of \method{as.dist}{deldir}). Gives a
  R CMD check Warning "S3 methods shown with full name in Rd file".

- Does not recognize importFrom in some cases. Happens with rdecorana.R
  where we have

  foo1 <- function() {}
  ##
  #' @importFrom stats filter
  ##
  foo2 <- function() {}

  importFrom stats filter (twice) and importFrom stats approx are in
  such positions as the only #' @importFrom lines between non-exported
  functions, and are not listed in imports in NAMESPACE. Gives a NOTE
  in R CMD check "Undefined global functions or variables".

- Does not handle replacement functions properly. This

  #' @export
  `sppscores<-.posvectord` <-
    function(object, value) {}

  is rendered in man page as

  sppscores<-.posvectord(object, value)

  which gives a Warning in R CMD check for "assignment in \usage". The
  correct rendering is:

  \method{sppscores}{posvectord}(object) <- value

  This may be due to inability to handle S3 methods outside
  tinyrox:::KNOWN_S3_GENERICS since the tinyrox code has an attempt to
  handle replacement functions.

- @author tag is non-functional. It is formally recognized, but
  \author{} field is not rendered in Rd file. Could be failed
  understanding of CRAN policy: some comments in tinyrox code say that
  author should be taken from DESCRIPTION and "no duplication in the R
  file", but function authors and package authors have different
  scopes and resolution, and CRAN has a file specific \author{} field
  for reason. Currently not a problem in natto with only one author so
  far, but would be a show stopper in, say, vegan.

- aesthetic: sometimes fails to automatically distinguish sections
  title, description and details when these are not explicitly
  tagged. tinyrox tries to do this, but fails in many natto files, and
  description and details are fused in one huge section. This was seen
  cNMDS.Rd, gausscircle.Rd, posvectord.Rd, qrao.Rd, rdecorana.Rd,
  sdca.Rd and slopediff.Rd (and perhaps unnoticed elsewhere). In one
  case both the title and description were given only as iap. These
  can be probably circumvented with explicit use of @title,
  @description and @details, but as other problems make the current
  tinyrox unusable, I did not try to fix this.

- Accepts only one section (paragraph) in @return and rest are
  dropped.
